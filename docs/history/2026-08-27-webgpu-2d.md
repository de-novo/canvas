# 2026-08-27 WebGPU 2D

## Date

2026-08-27

## Scope

Explicit `backend: "webgpu"` draws a 2D document on a GPU canvas
context. 2D `auto` stays Canvas2D. No compute, no 16 ms frame-budget
gate, no new official kind, no ThreeUI wrap, no new playground.

## Changes

- `resolveBackend("webgpu")` accepts 2D and 3D. Missing GPU is still
  `capability-unavailable`.
- `@de-novo/canvas-web` `createCanvas2D` attaches WebGPU when the
  facade asked for explicit `webgpu`. 3D `auto` still carries a
  WebGL2 fallback flag, so a 2D swap from that path stays Canvas2D.
- Official 2D nodes, plugin markers, sparklines, authoring overlays,
  and transform handles draw through one GPU pipeline. HTML nodes
  stay in the DOM overlay. Hit-testing and named operations stay on
  the same scene graph. Text metrics use a hidden Canvas2D canvas.
- `pnpm verify:webgpu` adds `2d-webgpu-bench.html` for draw stats
  and a rect hit. Playwright still cannot sample WebGPU pixels.

## Residual risk

- Playwright cannot sample WebGPU canvas pixels. The 2D gate uses
  renderer stats and hit-testing, not a canvas PNG sample.
- Custom `Canvas2DObject.render` callbacks still take a 2D context
  and do not present on the GPU canvas.
- 2D `auto` does not select WebGPU.
- GPU compute and a measured 16 ms frame-budget gate stay later work.

## Next action

Do not invent an official kind, wrap a ThreeUI room, or add a
playground. Next sayable slice is GPU compute or a pinned 16 ms
frame-budget gate.
