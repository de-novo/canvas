# 2d.ts 분해 — 유지보수 가능한 구조로

**Date:** 2026-07-29
**Status:** ✅ 완료 (동작 동일성 확인)

## Context

`packages/web/src/2d.ts`가 3,720줄이었고, 여기서 **같은 종류의 런타임 버그가 두
번** 났다. 둘 다 typecheck를 통과했고 둘 다 브라우저에서야 발견됐다:

- `selectionIds` — 2D 런타임 초기화 실패
- `activeAnimation` — **마우스 드래그 팬이 아예 동작하지 않음**

에러는 동일했다: `Cannot access 'X' before initialization`.

### 근본 원인

```
143  export function createCanvas2D(...) {
191–226   let 상태 20개
814       runtime = { ... }
909–941   셋업 실행: render(), resize(), start()
941       return runtime          ← 여기서 끝나지 않음
943–1358  inner 함수 21개          ← return 뒤, 호이스팅으로만 도달
```

`function`은 호이스팅되니 `return` 뒤에 있어도 돌아간다. 하지만 **`let`은
호이스팅되지 않는다.** 셋업이 부르는 `render()`가 `let` 11개를 읽으므로, 상태
선언 하나가 아래로 밀리는 순간 TDZ로 죽는다. 두 번의 버그는 우연이 아니라 이
배치의 산물이었다.

## 결과

**3,720줄 → 1,769줄** (런타임 클로저만 남음). 공개 API는 한 글자도 바꾸지 않았다
(`Canvas2DObject`, `Canvas2DRuntime`, `createCanvas2D`).

### 분할 판단

- **bounds와 edge-routing은 한 파일에 뒀다.** 엣지 바운드는 끝점에서 나오고,
  포트 끝점은 노드 바운드에서 나온다 — 상호 재귀라 나누면 순환 import가 된다.
- **상수를 따로 뺐다.** 렌더와 히트테스트가 같은 폰트·반경을 써야 "보이는 곳"과
  "눌리는 곳"이 일치한다. 그 결합을 파일로 명시했다.
- **렌더 ↔ 히트테스트 의존은 0**임을 확인하고 나눴다.

### TDZ 재발 방지

- `return runtime`과 셋업 부수효과를 **클로저 맨 끝으로** 옮겼다. 이제 모든
  선언 뒤에 실행된다.
- 상태 선언부에 이유를 적은 경고 주석을 달았다.

**실제로 막히는지 확인**: `selectionIds` 선언을 셋업 바로 위로 옮겨 재현을
시도했으나 **더 이상 깨지지 않았다.** 셋업이 맨 아래에 있으면 그 위 어디에
선언해도 안전하다.

## 하지 않은 것

- **`3d.ts`(3,073줄)는 건드리지 않았다.** 구조는 비슷하지만 모듈 스코프 가변
  상태(GPU 리소스 캐시 3개)가 있어 무상태 추출이 안 되고, `let`이 8개로 TDZ 노출도
  훨씬 작다. 2D와 중복된 헬퍼(색상 해석, 측정 포맷)를 공유로 빼는 것은 별도 작업.
- 동작 변경, 공개 API 변경, 성능 튜닝.
